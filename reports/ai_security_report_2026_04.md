## 2. Package Risk Profile

### 🔴 Ollama — HIGH RISK (7 CVEs, 3× CRITICAL/HIGH DoS, 1× RCE)

Ollama is the most actively targeted AI serving layer in Q1 2026. The Ollama MCP Server
command injection (CVE-2025-15063, CVSS 9.8) enables unauthenticated RCE — any deployment
exposing the MCP port is critically exposed. Three additional DoS CVEs confirm active
attacker interest in disrupting local LLM inference services.

**Recommended action:** Upgrade to ≥0.13.6, never expose MCP/API port to untrusted networks,
enforce network segmentation for all Ollama deployments.

### 🔴 LangChain / Langflow — HIGH RISK (8 CVEs incl. CRITICAL RCE)

CVE-2026-27966 (CVSS 9.8) in Langflow — the visual AI workflow builder built on LangChain —
allows full remote code execution. Multiple path traversal, SSRF, and prompt-injection
vulnerabilities in `langchain-core` compound the risk for agentic systems.

**Recommended action:** Upgrade langchain-core ≥1.1.14, langchain ≥0.3.2, audit all
`load_prompt` usages, restrict Langflow API endpoints to authenticated users only.

### 🟡 PyTorch / torch — MEDIUM RISK (4 CVEs, 1× CRITICAL via NVIDIA APEX)

The CRITICAL NVIDIA APEX vulnerability affects Linux training environments. A separate HIGH
CVE (CVE-2026-24747) affects tensor computation prior to PyTorch 2.x. Two additional CVEs
cover `torch.load` RCE (even with `weights_only=True` — a dangerous regression) and
improper resource shutdown.

**Recommended action:** Pin PyTorch ≥2.6, disable `torch.load` from untrusted sources,
audit NVIDIA APEX usage on Linux training clusters.

### 🟡 HuggingFace Transformers — MEDIUM RISK (14 OSV advisories, pattern: ReDoS cluster)

A systematic wave of ReDoS vulnerabilities was disclosed across Transformers tokenizers and
processors (MarianTokenizer, DonutProcessor, SETTING_RE, get_imports, get_configuration_file).
Additionally, CVE-2026-1839 allows arbitrary code execution in the `Trainer` class.

**Recommended action:** Upgrade transformers ≥4.51.0, avoid processing untrusted tokenizer
inputs in production, treat `Trainer` class with untrusted config as a privilege boundary.

### 🟡 LlamaIndex — MEDIUM RISK (8 OSV advisories)

SQL injection (CVE-2025-1793), insecure temporary files (multiple), and resource exhaustion
CVEs indicate LlamaIndex's RAG pipeline is an active target, particularly document ingestion
and file I/O paths.

**Recommended action:** Upgrade llama-index ≥0.12.x, parameterize all SQL queries, restrict
file system access in document loaders.

### 🟢 TensorFlow — LOW RISK (2 CVEs, both low-medium)

Only 2 CVEs in the 90-day window; one is in FFmpeg's TensorFlow backend (not core TF),
the other is an HDF5 search path issue. Indicates mature vulnerability management in the
TensorFlow codebase.

## 4. Threat Intelligence: Agentic AI Attack Surface

The April 2026 data reveals a clear shift: attackers are targeting the **agentic layer** —
the infrastructure that connects LLMs to tools, APIs, and execution environments.

- **Ollama MCP Server RCE** targets the Model Context Protocol layer
- **Langflow RCE** targets the visual agent orchestration surface
- **LangChain path traversal + SSRF** targets agent tool-use and document retrieval
- **PyTorch `torch.load` RCE** targets the model supply chain (malicious model files)

> The attack surface has expanded from the model itself to the entire inference and
> orchestration stack. Organizations must treat their LLM serving infrastructure with
> the same rigor as a public API endpoint.

## 5. Recommendations by Role

### For AI Platform Engineers
1. Enforce network segmentation — never expose Ollama/LocalAI ports to untrusted networks
2. Pin all AI framework versions in `requirements.txt` / `pyproject.toml` with hash verification
3. Scan model files before loading — treat `.pt`/`.safetensors` from untrusted sources as adversarial inputs

### For MLOps / LLMOps Teams
4. Disable `torch.load` pickled format for production model serving — use SafeTensors exclusively
5. Audit all LangChain `load_prompt` and template rendering code for path traversal
6. Review Langflow deployments — apply authentication middleware immediately

### For Security Teams
7. Add AI/ML package CVEs to your SIEM watchlist: tensorflow, torch, transformers, langchain-core, ollama
8. Subscribe to OSV alerts for PyPI AI packages
9. Include ReDoS testing in AI application security reviews — especially tokenizer pipelines
